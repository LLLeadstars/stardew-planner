# 活动身份与重算策略

**Status**: accepted

系统生成的日程活动（重复系列实例、作物照料活动）必须能被稳定识别，否则每次打开日期或补改历史都可能在重算时重复生成，或抹掉玩家记录。我们为三类活动分别确定身份：手工活动＝独立身份；重复活动实例＝「系列 + 日期」；照料活动＝「作物批次 + 日期 + 活动类型」。重算按身份执行「存在则更新、不存在则新增」，绝不先删后建。

考虑过但未采用的替代方案：按「日期 + 活动类型 + 名称」模糊匹配（同类活动并存时会误配）；每次重算先清空当天系统活动再重建（会丢失玩家手动调整与完成记录，与「只自动调整未受保护的系统安排」的方针冲突）。

后果：删除某天系列实例记为该身份的「跳过」状态，重算不会让它复活；数据层需要保存稳定的系列标识、批次标识，以及「玩家手动修改 / 已完成」的保护标记。
