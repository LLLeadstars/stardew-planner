# 星露谷日程管理器 V1：通往可实施规格的决策地图

状态：已发布并核验。本文件保留为建图时的草稿快照，后续状态与决策以 [GitHub 决策地图](https://github.com/LLLeadstars/stardew-planner/issues/1) 为准，不再在此维护副本。
地图标签：wayfinder:map。

## Destination

确定星露谷日程管理器 V1 的产品与技术方案，产出用户认可、可直接用于实施的规格。
规格明确功能边界、交互、领域模型、活动数据和估算规则、排程语义、持久化、技术架构及可验证的验收标准。

## Notes

- 建图背景见同目录 v1-charting-baseline.md；发布时将该文件内容纳入地图的初始背景附件或正文，保证 GitHub 上可访问。
- 使用中文交流，每轮集中讨论 1～2 个关键问题，先解释选项影响，再请用户决策。
- 每次工作先读取 grilling 和 domain-modeling；研究问题使用 research，交互或逻辑原型使用 prototype。
- GitHub 是正式任务系统。子任务使用原生 sub-issues 关系，阻塞使用原生 Issue dependencies；仅在功能不可用时采用仓库配置规定的回退方式。
- 本次工作以确定方案为主。允许为决策制作可丢弃原型；用户明确要求最终产出规格，因此规格编写纳入本地图。正式产品实现、部署不在本地图内。
- 领域术语按需记录到 CONTEXT.md，实施细节写入规格；仅对符合条件的重要取舍建立 ADR。
- 决策详情存于对应子任务的结论评论；本地图只保留结论摘要及链接。
- 规格完成标准：关键决策均已解决；需求有验收标准；数据和估算有证据或明确可执行的降级规则；不存在阻塞实施的 TBD；获得用户对最终规格的认可。

## Not yet specified

- 活动研究结果将决定估算规则需要多精细、需要何种校准或验证，以及规则不可靠时如何降级。
- 日程编辑原型可能暴露新的操作和状态边界，需要据反馈进一步拆分问题。
- 后续分享、存档导入与跨天规划对当前模型的必要影响，要在实际模型出现后判断；仅保留有依据的扩展空间。
- 待产品与技术决策收敛后，明确最终规格的章节、验收场景和实施交接边界。
