> 本分支（`prototype/issue-6-day-plan`）保存原型的完整快照，作为决策的 primary source。

## 当前已定的交互决定

完整决策记录发在 [#6](https://github.com/LLLeadstars/stardew-planner/issues/6) 的结论评论里（不随本分支分发）。要点：

- 日程形态：**融合**——时间轴与列表合为一个按时间定位的单列表，不做两栏并排
- 重叠表达：包含关系用**缩进**；部分重叠用**脊柱 + 「同时进行 · 重叠 Xm」**
- 拖动语义：压缩轴上**不做连续拖动**，改用**离散落点**（空隙起点 / 卡片上半＝紧贴到它前面 / 卡片下半＝紧贴到它后面）；相邻两项互换开始时刻用 ↑↓
- 空隙留白：**紧凑**（压到 30px）与**真实比例**（不封顶）两档，**默认真实比例**
- 门店判定：**建筑可进入**与**服务可用**拆成两个独立结论分别保存与显示（见下节）

## 门店判定：两个独立维度

`#12` 的门店矩阵要求「**建筑可进入与服务可用必须分开保存**」。原型据此把每个门店的判定拆成两个独立结论：

| 维度 | 含义 | 例子 |
|---|---|---|
| `access` 可进入 | 玩家能不能进这栋建筑 | 皮埃尔通常可进到 21:00 |
| `service` 可交易 | 柜台能不能办事 | 皮埃尔通常只能交易到 17:00 |

两者会真的分叉，这正是拆开的价值：

- 木匠商店**罗宾在农场施工**时，房屋仍可进入（09:00–20:00），但全天办不了事
- 木匠商店**周二**正式关闭，但约 09:40 / 约 20:00 罗宾经过柜台仍有瞬时交易机会
- 铁匠铺**城镇钥匙**只改变进门，不把服务变为可用

界面上这对维度出现在两处：活动卡片上的门店块（两行）、左信息栏的「今日检查」（两行）。

条件性交易窗口一律标为**技巧**，不写成固定的 10 分钟营业段（矩阵明确要求）。

## 关于自检脚本（有意偏离技能）

`prototype` 技能的反模式清单第一条写着「**Don't add tests.** A prototype that needs tests is no longer a prototype.」

这里保留自检是**有意的偏离**：该原型的模型层承载大量日期算术与领域规则（10 分钟粒度、工具升级 D+2、包含关系、时长来源优先级链、门店条件判定）。这些规则若**静默算错**，玩家就是在对着一个错误的物件做判断，反馈会污染决策——比不做原型更糟。

所以这两份脚本守的不是产品质量，而是**判断对象的有效性**。代价是它们占约 29KB，且模型改动时须同步维护。

## 已知的占位与缺口

- **浇水估算系数是占位值**（每格 0.5 分、每次往返补水 5 分、密集 ×1.25 / 分散 ×1.5、校准上界 120 格）。真实数字待 `执行浇水耗时实测与校准`（[#11](https://github.com/LLLeadstars/stardew-planner/issues/11)）——该票的进度文件状态为「协议已准备，尚无实机样本」，因此占位系数暂留。界面内可展开查看。
- **门店判定的实机回归未做**。规则已对齐 `docs/research/stardew-shop-matrix-1.6.15.md`（核验日期 2026-09-18）的「V1 保守状态」列，但该矩阵末尾的实机回归清单在执行前，凡涉及随机分支或版本未证实的状态（姜岛度假村随机出行、夜间/特殊节日例外、铁匠铺建门独立时段）一律保持**未知**，不伪造成确定结论。
- **作物批次只做最薄一层**：按已完成种植活动派生，按数据字段算首次收获日期，不做逐日生长模拟。
- **重复活动只是一个次数输入框**，不生成实例、不做重算。
- **所有活动不分日期**：切换「查看日程」日期不会过滤活动列表（跨天规划在 V1 范围外）。
- **拖动的手感未优化**：落点语义已定，具体的跟手、吸附、幽灵元素等留给实现阶段。
